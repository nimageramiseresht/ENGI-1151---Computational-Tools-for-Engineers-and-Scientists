# ENGI 1151 Computational Tools for Engineers and Scientists

Weekly lecture notes as web pages, with live Python (JupyterLite + Pyodide)
running in the student's browser. No server, no installs, no accounts.

The site opens on a week selector (`index.html`). Each week page mixes the
lecture text with diagrams, interactive examples, quick-check questions,
step-through code tracers, live Python windows under every code block, empty
Python boxes for exercises, and a full practice notebook at the bottom.

## What's in the repo

| Path | Purpose |
|---|---|
| `index.html` | Landing page: choose a week. |
| `week1.html`, `week2.html`, `week5.html` | One page per week. |
| `assets/site.css` | Shared styles for every page (light and dark mode). |
| `assets/site.js` | Shared behaviour: the **week list** (`WEEKS`), live Python windows, practice notebook, quick checks, tabs, tracers. |
| `assets/week1.js`, `assets/week2.js` | Interactive widgets for those weeks. |
| `assets/traces.js` | Generated by `tools/make_traces.py`: real Python traces for the "Step through" boxes. |
| `content/*.ipynb` | Practice notebooks, embedded at the bottom of each week page. Every notebook in this folder is built into JupyterLite. |
| `.github/workflows/deploy.yml` | Builds JupyterLite into `lite/` and publishes everything to GitHub Pages on every push to `main`. |
| `requirements.txt` | Pinned JupyterLite build tools. |

## Adding a new week

1. Copy `week2.html` to `week3.html` (it shows every building block), change the
   title, `data-week="3"` and `data-notebook="week3_….ipynb"` on `<body>`, and
   replace the sections.
2. Put the practice notebook in `content/`.
3. In `assets/site.js`, replace `{ n: 3, soon: true }` in `WEEKS` with the real
   entry (`file`, `title`, `blurb`, `topics`). The landing page, the week
   buttons in the top bar and the previous/next links update automatically.
4. Optional: add step-through examples to `tools/make_traces.py` and run
   `python tools/make_traces.py`.

### Building blocks you can use in a page

- `<figure class="code" data-runnable>` code block with an **Open live Python** button.
  Add `data-setup="name"` to run hidden setup code first (from a
  `<script type="text/plain" id="setup-name">` block), and `data-hint="…"` for a note.
- `<figure class="code sandbox" data-runnable>`: an exercise box that opens an empty Python window.
- `<pre class="out">` straight after a code block shows its expected output.
- `<div class="exercise">`, `<div class="note">`, `<div class="example">` coloured boxes;
  `<details class="solution">` for a hidden solution.
- `<div class="quiz" data-answer="1">` quick check (index of the correct button, starting at 0).
- `<div class="tracer" data-trace="id">` step-through box for a trace in `tools/make_traces.py`.
- `<figure class="diagram">` with an inline SVG using the `dg` classes, so it follows light and dark mode.

## Publishing

Push to `main`. The *Build and deploy* action runs (about 1–2 minutes) and the
site updates at `https://<you>.github.io/<repository>/`. GitHub Pages must be set
to **Settings → Pages → Source: GitHub Actions** (already done for this repo).

## Previewing locally

Opening a page directly from disk works: the live windows fall back to the
public JupyterLite demo. To preview the full site including the embedded notebooks:

```bash
pip install -r requirements.txt
jupyter lite build --contents content --output-dir dist/lite
cp index.html week*.html dist/ && cp -r assets dist/
python -m http.server -d dist 8000   # then visit http://localhost:8000
```

## Notes for students

- The first live window takes 10–20 s to start while Python downloads; after that it's cached.
- `input()` opens a small text box under the cell. If none appears (some private-browsing
  windows block the service worker it needs), replace `input(...)` with a value.
- NumPy and Matplotlib load automatically when imported.
- Notebook edits are saved in the browser only. Use *File → Download* to keep a copy.
