1Introduction

flow control

Python runs the statements one after another, from the top of the cell to the bottom.

Step through the code. When a changes on line 6, does result change too?

Flow control = the order in which statements are executed. By default Python is sequential: each statement runs before the next one starts. Click "Next line" through the panel. result = a + b is evaluated once, giving 45. Changing a afterwards does NOT recalculate result: it stays 45. To update it, the calculation must be written again. Why we need more than sequence: ask for an input and choose between two messages; repeat a calculation 1000 times; iterate until an error is below a tolerance; ignore an invalid sensor value without stopping.

sequenceselectionrepetition

statements run top to bottom

Selection: choose a path

Repetition: loop

Every program is built from three kinds of flow. Sequence: one statement after another (what we had last week). Selection: test a condition and choose one block. In Python: if, elif, else. try / except is also a kind of selection: it chooses a different block when an error occurs. Repetition: run the same block several times. In Python: for and while. break, continue and pass control what happens inside a loop. This is the map for the whole lecture: section 2 builds the conditions, section 3 is selection, sections 4–6 repetition, section 7 errors.

3Indentation and colons

indentationcode blockcolon

Fix this code: it has a missing colon. Then delete the 4 spaces before print and run it again.

temperature = 45.0

if temperature > 40.0
    print("The temperature is high.")

print("Check finished.")
Python has no "end" keyword. Indentation decides which statements belong to an if, a loop or a function: the indented lines form the code block. Convention: 4 spaces per level. Editors insert 4 spaces when you press Tab. Never mix tabs and spaces. Every header line (if, elif, else, for, while, try, except...) ends with a colon. When the indentation goes back to the previous level, the block has ended: print("done") runs once, after the loop. Live demo: run as it is → SyntaxError: expected ':'. Add the colon → works. Remove the indentation → IndentationError: expected an indented block. Restore it.

3Order of conditions

most restrictive firstfirst True wins

Put the most restrictive condition first. Python stops at the first True condition.

The order of conditions matters, because only the first True block runs. Drag the slider: watch which path lights up (41 → very hot, 30 → warm, 10 → cool). Now tick "incorrect order" with 41 °C: temperature > 25.0 is checked first, it is already True, so we print "It is warm." The very hot branch can never be reached for any temperature! Rule: from the most restrictive condition to the least restrictive. Next slide: run both versions.

Loops

Section 4: repetition with for and while.

4for versus while

for → a series of valueswhile → a condition

for item in series:

for counter in range(3):
    print("Counter:", counter)

while condition:

counter = 0
while counter < 3:
    print("Counter:", counter)
    counter += 1
Two loop types, and the difference is in the header line. for is followed by a SERIES of values (a range, a list, a string...): the body runs once per value, and the loop variable takes each value in turn. You know in advance how many passes there will be. while is followed by a logical CONDITION (a Boolean expression from section 2): the body repeats as long as the condition is True. Something inside the body must eventually make it False. Both boxes print the same three lines: run them. Rule of thumb: for when you have the values; while when you repeat until something happens (convergence, a sensor reading, user input).

4.1for loops

iterationloop variable

for iteration in range(5):
    print("Iteration:", iteration)
A for loop iterates over an iterable object: a list, tuple, string, dictionary or range. range(5) does not create a list; it represents the integers 0, 1, 2, 3, 4. The final value 5 is excluded. In each iteration the loop variable (here called iteration) is assigned the next value. Run: five lines, 0 to 4.

4.1.1Using range()

startstop (excluded)step

print(list(range(4)))
print(list(range(2, 6)))
print(list(range(0, 10, 2)))
print(list(range(5, 0, -1)))
Three forms of range(): range(stop): starts at 0, stops BEFORE stop → 0 1 2 3. range(start, stop): 2 3 4 5. range(start, stop, step): 0 2 4 6 8. A negative step counts backwards: 5 4 3 2 1. The dashed circles are the stop values: never included. list(...) is used here only to display all the values at once. Arguments must be integers, and the step cannot be 0 (try range(0, 10, 0) → ValueError).

4.1.2Iterating over a list

iterableone element per pass

temperatures = [20.5, 22.1, 25.8, 27.3]

for temperature in temperatures:
    print("Temperature:", temperature)
A for loop can go directly through the elements of a list; no index needed. During each iteration the variable temperature refers to one element. Good naming habit: plural for the list (temperatures), singular for the loop variable (temperature).

4.1.3enumerate()

index and valuestart=1

temperatures = [20.5, 22.1, 25.8]

for index, temperature in enumerate(temperatures):
    print(index, temperature)

for test, temperature in enumerate(temperatures,
                                   start=1):
    print("Test", test, ":", temperature)
enumerate() gives both the index and the value on each pass, so you need two loop variables separated by a comma. By default the counting starts at 0 (like list indices). start=1 is friendlier for "Test 1, Test 2..." labels. Run: first three lines 0/1/2, then Test 1/2/3.

4.1.4zip()

pairing two listsstops at the shortest

times = [0.0, 1.0, 2.0, 3.0]
displacements = [0.0, 2.5, 5.1, 7.8]

for time, displacement in zip(times,
                              displacements):
    print("Time:", time,
          "Displacement:", displacement)
zip() goes through two (or more) lists side by side: pass 1 takes the first element of each, pass 2 the second, and so on. Useful when related measurements are stored in separate lists (time and displacement from the same test). zip stops when the SHORTEST list runs out, so related lists should have the same length. Demo: delete 3.0 from times and run.

4.1.5Accumulating results

running total+=

loads = [12.5, 8.0, 15.5, 10.0]

total_load = 0.0
for load in loads:
    total_load += load

average_load = total_load / len(loads)
print("Total:", total_load, "kN")
print("Average:", average_load, "kN")
A very common pattern: build up a result while the loop runs. 1. Create the variable before the loop and set it to 0. 2. Inside the loop, add to it: total_load += load is shorthand for total_load = total_load + load. 3. After the loop (back to the left margin) use the result. len(loads) gives the number of elements (4). Output: Total 46.0, Average 11.5. Question: what goes wrong if total_load = 0.0 is moved inside the loop? (It is reset every pass → total 10.0.)

4.2while loops

conditioncounterupdate!

while counter < 3:

checked before every pass; the loop stops when it becomes False

counter = 0

while counter < 3:
    print("Counter:", counter)
    counter += 1
A while loop repeats while its condition is True. The condition is a Boolean expression, checked BEFORE each pass. Step through: watch counter change and the condition being checked 4 times (True, True, True, False). counter += 1 is essential: without it the condition stays True forever → infinite loop. Demo: delete counter += 1 and run → it never ends; press ■ Stop on the code box. (In Jupyter: the ■ interrupt button.)

4.2.1Engineering example: iterative calculation

toleranceconvergencemaximum iterations

error = 1.0
tolerance = 0.01
iteration = 0
maximum_iterations = 100
while error > tolerance and iteration < maximum_iterations:
    error = error / 2.0
    iteration += 1
    print("Iteration:", iteration, "Error:", error)
if error <= tolerance:
    print("The calculation converged.")
else:
    print("The calculation did not converge.")
Many numerical methods repeat a calculation until the error falls below a tolerance: equation solvers, optimisation... Here the error is halved each pass: 0.5, 0.25, ... 0.0078125 after 7 iterations, which is below 0.01, so the loop stops. An iterative method is NOT always guaranteed to converge, so we add a safeguard: iteration < maximum_iterations, combined with "and". After the loop, an if statement reports which condition ended it. Demo: set maximum_iterations = 5 → "did not converge". Or tolerance = 0.0001 → more iterations. Intentional infinite loops (while True:) are used for monitoring and data acquisition, but need a way out such as break: see the exercise at the end.

5.1break

stop the whole loop

temperatures = [22.0, 24.5, 27.1,
                85.0, 25.3]
maximum = 80.0

for temperature in temperatures:
    if temperature > maximum:
        print("Unsafe:", temperature)
        break

    print("Accepted:", temperature)
Sometimes the normal execution of a loop must change. break terminates the innermost loop immediately; the program continues after the loop. Engineering use: stop a search as soon as an unsafe measurement is found. Step through: 22.0, 24.5, 27.1 accepted; 85.0 triggers break; 25.3 is NEVER checked. (Variable names shortened on the slide: maximum = maximum_temperature in the handout; messages shortened.) Simple version from the handout: for i in range(10): if i == 5: break; print(i) → prints 0 to 4.

5.2continue

skip one pass

measurements = [12.5, -999.0, 13.1, 12.8]
invalid_value = -999.0

for measurement in measurements:
    if measurement == invalid_value:
        continue

    print("Valid:", measurement)
continue skips the REST of the current iteration and moves on to the next one. The loop itself carries on. Engineering use: ignore an invalid sensor reading (here -999.0 is a common "no data" code) without stopping the analysis. Step through: 12.5 printed; -999.0 skipped; 13.1 and 12.8 printed. Contrast with break: break abandons the loop, continue abandons only one pass. Handout example: for i in range(5): if i == 2: continue; print(i) → 0 1 3 4.

5.3pass

placeholderdoes nothing

statementwhat happens
breakleaves the whole loop
continueskips to the next pass
passnothing at all: a placeholder where Python needs a statement
 
temperature = 25.0

if temperature > 80.0:
    pass   # TODO: shut down the system
else:
    print("Temperature in the expected range.")
pass performs no operation. Python requires at least one statement in every block; pass fills the gap while the real code is not written yet. pass does NOT end a loop and does NOT skip to the next iteration: do not confuse it with break or continue. Demo: delete the pass line and run → IndentationError (the block is empty).

6Nested loops

outer loopinner loopcombinations

load = 100.0load = 200.0
length = 1.0pass 1pass 2
length = 2.0pass 3pass 4
length = 3.0pass 5pass 6

the inner loop runs through every load before the outer loop moves to the next length: 3 × 2 = 6 passes

lengths = [1.0, 2.0, 3.0]
loads = [100.0, 200.0]

for length in lengths:
    for load in loads:
        print("Length:", length, "Load:", load)
A loop inside another loop is a nested loop. The outer loop processes one length at a time; for each length, the inner loop runs through ALL the loads. The table shows the order of the 6 passes: read it row by row. Uses: parameter studies, matrices, numerical grids, 2-D measurement data (handout example: rows of a measurement grid). Cost grows quickly: 1000 lengths × 1000 loads = 1 000 000 passes.

Exception handling

Section 7: responding to expected errors with try and except.

7try and except

exceptiontryexcept ValueError

try:
    number = int(input("Enter an integer: "))
    print("You entered:", number)

except ValueError:
    print("Not a valid integer.")
An exception is an error detected while the program is running: invalid input, division by zero, a missing file, an invalid conversion. If it is not handled, Python stops the program (or notebook cell) with an error message. try: Python runs the statements in the try block. If int() cannot convert the input, it raises a ValueError, and Python jumps to the matching except block instead of crashing. Run with 12 → "You entered: 12". Type abc in the input box → "Not a valid integer." Try 12.5 too (also a ValueError for int()). Good practice: name the exception (except ValueError:) rather than a bare except:, which would hide unrelated programming errors.

7.2–7.3The else and finally clauses

else: only if no errorfinally: always

blockno errorerror
tryrunsstops at the error
exceptskippedruns
elserunsskipped
finallyrunsruns

else keeps the try block short; finally is for clean-up, such as closing a file

try:
    value = float(input("Enter a value: "))

except ValueError:
    print("The input must be numerical.")

else:
    print("The entered value is:", value)

finally:
    print("Input processing has finished.")
else (optional): runs only if the try block finished WITHOUT an exception. It keeps the try block limited to the statements that can actually raise the expected error, so it is clear which line failed. finally (optional): runs whether or not an exception occurred. Used for things that must always happen: closing a file, releasing a resource. The handout shows them as two separate examples; here they are combined. Run with 12.5 (try, else, finally) and with abc (try, except, finally). Message: exception handling is for operations that may reasonably fail; it must not be used to hide programming errors.

8Summary

  • Statements normally run in sequence
  • Boolean expressions: == != > < >= <= → True / False
  • Combine with and, or, not
  • if / elif / else: the first True block runs; order matters
  • Indentation and : define the blocks
  • Nested conditions, or simplify with and
  • for goes through a series: range(), lists, enumerate(), zip()
  • while repeats while a condition is True; add a maximum number of iterations
  • Running totals: start at 0 before the loop
  • break stops, continue skips, pass does nothing
  • Nested loops for combinations and grids
  • try / except / else / finally for expected errors

Engine health monitoring: a possible solution

while Trueenumerate(start=1)

while True: one pass = one sweep of all 15 sensors  ·  for … enumerate(readings, start=1): sensor numbers 1 to 15  ·  if: compare with the limit  ·  ■ Stop ends it

safe_limit = 287    # °C

while True:
    readings = read_sensors()
    for number, temperature in enumerate(readings, start=1):
        if temperature > safe_limit:
            print('temperature exceeded the safe limits on sensor number', number)
Walk through the solution: outer infinite while loop = continuous monitoring; inner for loop = one check of each sensor. Run it and let it go for a few seconds, then press Stop. Extensions to discuss: print the temperature too; count how many times each sensor exceeded the limit (a list of 15 zeros and +=); stop with break after 3 consecutive exceedances; wrap read_sensors() in try/except in case a sensor fails.
